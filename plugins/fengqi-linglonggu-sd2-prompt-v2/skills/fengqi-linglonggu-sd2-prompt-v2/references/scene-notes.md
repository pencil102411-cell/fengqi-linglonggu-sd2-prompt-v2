# 场记：当前场次的制作记忆

场记用一份场次记忆.md保存《风起玲珑骨》当前场次的有效要求、采用版本、镜头接点与制作进度。它是可续做的制作备忘录，不是聊天归档、剧本正典或新的提示词格式。设计参考“横屏影视提示词 Agent 2.0”的场次记忆机制，运行时不依赖安装该插件。

## 入口与保存位置

- “建立场记”“启用本场场记”“保存这场的要求”：明确授权后建立文件；普通生成、一次返修或一句“继续下一镜”不自动新建。
- “读取场记”“继续这一场”：先核对作品、集数／场次与适用目录，再读取续做摘要、全场要求及当前镜头相关状态；只读不自动写入。
- “更新场记”“记住这个改法”“后面保持”：已有场记按授权范围合并；初次使用时，只有明确要求把本场要求保存为场记才建文件。
- “本场持续维护场记”：为当前场次开启持续维护；“暂停维护”停止自动写入；“不再使用场记”同时停止继承，恢复需明确要求。

优先使用用户指定的场次项目根目录，否则使用当前工作目录；目标只有该目录下的场次记忆.md。先确认这里确实是本场制作目录。若当前目录是插件安装目录、插件源码仓库或包含多场且归属不明的总目录，不写进去，先说明需要本场目录。已有文件属于另一场时不覆盖、不混用；多场各放各自的场次目录。路径明确、当前场次明确就直接执行，不重复确认。

首次创建按[场记模板](scene-notes-template.md)填已知信息；空项保持待确认，不为了填表编造或中断创作。兼容已有场次记忆.md，不强制迁移和重建。旧文件未写维护方式时默认“明确维护”；被明确停用的旧记录不因文件仍存在而重新启用。

## 两种维护方式

**明确维护（默认）**：只在用户要求保存、继承、更正或撤回已记录内容时写入；只读、讨论、一次普通返修不自动写入。一次镜头调整只作用于指定镜头，不升级为全场规则。

**本场持续维护**：用户明确开启后，在本场后续工作中保存已确认要求、已选定版本和制作进度，不逐次索要授权。未经采用的创意只在确有续做需要时列为待定，不进入有效要求。持续维护只覆盖当前场次，不授权制作下一镜、改插件、提交或上传文件。

## 记录内容

1. **场次归属**：作品、集数／场号、适用目录、已有镜号／视频条号、剧本与资产位置、目标模型版本。镜头与视频条是两层编号，沿用用户命名；一条视频内可包含多个镜头。
2. **有效要求**：具体画面、对白、动作、表演、机位、光影、禁项及其适用镜号／故事时点／方案；标明必要来源。只记录真正影响续做的内容，保留细节。
3. **采用版本**：对象、选定文件或版本、参考用途、用户选择依据。没有版本号可记文件名；不按文件时间或生成先后自动改用“最新”。提示词、参考图和成片分别记录。
4. **连续性接点**：位置、朝向、姿态、动作阶段、视线、情绪强度、身体版本／伤势、持物与手别、空间轴线、环境、光源和特效余态。只填写对当前与后续镜头有意义的项目。
5. **进度与续做**：提示词已完成、候选已生成、用户已采用、成片已核验分别记录；写清待验证、待返修和下一步。它们不是必须逐级审批的流程，待办不等于执行授权。

素材记文件名／路径／版本与用途，不将某轮的 @图片 N、@视频 N 编号永久绑定。新一轮仅按实际提供且可用的素材重新编号；旧路径不能证明当前已上传或自己已看过。目标模型与摄影设置留在场记和镜头设计摘要中，不能因此塞进生成提示词的禁用元数据位置。

## 设计与成片分开

每个关键接点分别记录：

- 设计目标／批准情况：用户确定的动作和终态；没有成片依据时写“预计，待验证”。
- 实际观察／来源：亲自查看的成片、用户明确描述或对应项目资料；附采用文件、版本及必要的秒数／帧位置。

用户选定方案不等于动作已经生成；用户描述不能写成自己看片核验；文件存在不能证明画面内容。尚无成片可继续设计下一条，不能强制用户先补视频。

按场次、镜号／故事时点和方案分支区分状态，不以维护日期排序剧情。镜2握瓶与镜5放瓶可以同时有效；返修前镜不能用“最新状态”覆盖后镜。区分角色自身左右、画面左右和场景方位，稳定光源绑定场景位置，正反打按实际机位换算。

前镜采用版本或终态变化时，只检查依赖它的后镜接点，标“待复核”及影响原因，不擅自重写后镜。新设计目标可以与旧成片观察并存，旧成片只提供返修依据，不阻止用户改稿。

## 继承、局部返修与冲突

当前用户明确要求优先于旧场记。仅继承仍有效且适用于当前镜号、故事时点和方案的内容；待定建议、撤回项和已被替代的版本不继承。场记不修改项目正典，不引入尚未发生的剧情；当前用户明确改编可记为本场设计偏离。

完整提示词仍按原技能的瑞宝PRO六段交付包、九个内部标题、逐镜摄影头部和5000字符上限交付；场记不采用参考插件的四区块格式。

“只改镜头X，其余不动”时仍先遵守逐字冻结规则。场记只能提供背景依据，不能补写或整理冻结区。需要上一版完整提示词时，读取用户已采用的完整提示词文件原文或取得完整消息；场记摘要、路径、旧接点都不能替代可逐字比较的基线。若用户只要替换段，就只返回替换段；已授权的场记维护在文件中完成，不往替换段附加场记报告。

只修改场记某一项时，按指定记忆范围合并，不触发视频提示词基线检查或强制生成六段包。未请求生成或返修时不顺带生成提示词；同时请求续做则完成授权的创作部分。

## 合并与保存

写前读取原文件和相关有效内容，核对归属；保留未涉及的有效条目。对同一对象、范围、故事时点和方案中的冲突，以用户最新明确要求替代旧要求，重要替代简记理由。全场要求与单镜例外可同时成立，例如“全场无泪，镜7除外”。重复内容不重复追加。

有效改法须有结果依据与适用条件；未验证尝试留待定。撤回项退出有效区；用户明确要求删除某项时，从本文件有效区、经验及变更记录一并清除，不复制到历史区继续保留；不声称同时清除了外部聊天或版本历史。

提交写入前检查文件是否被其他任务改动；变动则重读合并，不用旧副本覆盖，也不声称已经实现并发锁。保存后回读验证新内容与未改内容，再简短报告实际路径和变化。无变化不写；读取／保存失败时不猜旧内容、不用空模板覆盖原件、不虚报已记住，说明失败并继续可独立完成的创作。

## 数据边界

只在使用者当前场次项目中保存实际场记，不写入SKILL.md、插件仓库、references、其他场次或Codex全局记忆。不自动Git提交、上传、跨电脑同步，不建立数据库、后台进程或每轮历史快照。插件升级仅更新规则与模板，不触碰用户场记。跨电脑续做由用户自行携带场次记忆.md和相关素材，并在新任务中明确提供路径；不承诺宿主自动加载或每次压缩前自动保存。

## 行为核对示例

| 当前请求或状态 | 应有行为 |
|---|---|
| 生成下一镜，尚未启用场记 | 完成提示词，不新建记忆文件 |
| 建立本场场记，仅有已批准提示词 | 保存设计目标，成片状态标预计待验证 |
| 只读取场记 | 读取并说明当前状态，不写入 |
| 只把场记里镜2改为右手持瓶 | 只改该条，不索要完整视频提示词，不改镜5 |
| 持续维护中，镜2改用另一条视频 | 更新采用版本；仅依赖镜2的后镜标待复核 |
| 只返回镜2替换段，同时已启用持续维护 | 冻结其余提示词；维护获授权记录，回复只含替换段 |
| 场次文件属于另一集或另一场 | 不套用、不覆盖，澄清归属；独立创作继续 |
| 暂停维护或无法保存 | 停止自动写入，说明必要情况，不停止制作 |
